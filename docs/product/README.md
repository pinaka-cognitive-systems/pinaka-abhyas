# Product

Product documents for Pinaka Abhyas. They say what the product is, for whom, and
what it will not do. They describe the product to be built, not the code that
exists. They name roles, never people.

- `boundary.md`: the student, the job, the non-goals, the principles, and the
  decision rule. It sits above every other document, and nothing may contradict
  it.
- `objects.md`: the object model and the glossary. One word per thing.

The PRD and the technical design come next and hang from these two pages. A gap
analysis then measures the code against them.

A change to a non-goal, a principle, the exam list, or the decision rule in
`boundary.md` needs a written decision that the product owner approves.
