# W1-12 independent core-math cross-check

An independent twin of the TypeScript mastery engine's core math (SPEC section 3,
ADR 0012), written from the specification text alone. Its only job: replay the same
update sequences through two implementations and prove they agree within tolerance —
or pin down precisely where they don't.

## Isolation contract

`glicko_lite.py` and `generate_cases.py` were written **without ever reading**
`engine-ts/src/`, `engine-ts/tests/`, or `engine-ts/refutation/`. They derive entirely
from `engine-ts/SPEC.md` section 3 and `docs/adr/0012-glicko-lite-mastery.md`. That
isolation is the entire value of the check: an independent reimplementation catches
spec-vs-code drift that a shared codebase cannot.

`compare.mjs` is the **only** file that touches the TypeScript engine, and it imports
`engine-ts/src/mastery.ts` blindly — the import surface (`updateSkill`, `applyIdleDrift`,
`FRESH_SKILL`) and the observation field names were discovered purely by probing the
module's runtime behavior, never by reading its source.

## Files

- `glicko_lite.py` — the Python reference for SPEC section 3: expectation, the one-step
  Laplace update, and idle drift with its two separate clocks (variance grows per idle
  day at `(1.5^2 - 0.25^2)/90`; rating fades by `exp(-idleDays/120)`).
- `generate_cases.py` — deterministic generator. Implements `mulberry32` (a seedable
  32-bit PRNG) in pure Python so a JavaScript twin seeded identically reproduces the
  same stream. Emits `cases.json`: 500 sequences spanning ability `[-3, 3]`, all three
  difficulty labels, both item types, empirical-difficulty overrides, idle gaps from
  minutes to 200 days, and event counts from 1 to 300. Each case carries its inputs and
  the Python reference's final `(rating, deviation)` to 12 decimal places.
- `cases.json` — generated fixtures (regenerated by `run_compare.sh`).
- `compare.mjs` — the comparator. Loads `cases.json`, replays each case through the TS
  `updateSkill`, and measures the absolute difference against the Python reference.
- `compare.test.ts` — the comparator wrapped as a vitest spec.
- `run_compare.sh` — the runner.

## How to run

From anywhere in the repo:

```sh
# Default: regenerate cases.json, then run the direct comparator via tsx.
crosscheck/run_compare.sh

# Same comparison, but driven through engine-ts's vitest:
crosscheck/run_compare.sh vitest
```

Both invoke from inside `engine-ts/` (where `node_modules` lives) and use `npx -y tsx`
so the blind `.ts` import resolves. Neither modifies any `engine-ts` config.

To regenerate fixtures alone:

```sh
python3 crosscheck/generate_cases.py
```

Requires only the system `python3` (stdlib only) and `tsx`/`vitest`, which are available
via `npx` inside `engine-ts`.

## Tolerance contract (SPEC section 9)

> Internal arithmetic is IEEE double; cross-implementation checks (W1-12) use tolerance
> **1e-6 on ratings and deviations**, exact on integers and orderings.

The comparator passes only if the maximum absolute difference in both rating and
deviation, across all 500 cases, is `<= 1e-6`.

## Current result

**FAIL.** 32 of 500 cases disagree; max rating diff 0.2646, max deviation diff 0.0464.

Root cause (a specification gap, not an arithmetic bug): the TypeScript
`applyIdleDrift` **skips all drift when `attempts === 0`** — a never-attempted skill does
not fade its seeded rating or grow its variance across an idle gap. SPEC section 3 says
idle drift is "applied before each update and on read" with no `attempts` precondition,
so the Python reference drifts unconditionally on the first event's time gap. The two
agree on every event after the first. See the W1-12 report for the minimal reproducer
(`case-0416`, a single event).

This check is wired to fail until either the spec states the `attempts === 0` exemption
or the engine drops it. Per the W1-12 brief, the cross-check does not modify either
implementation; it reports the divergence.
